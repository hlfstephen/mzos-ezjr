# 12 · Bank 规划：一个功能模块一个 bank

> 目标：把「靠编译器优化挤空间」换成「按模块分 bank 给空间」。
> 编译回到 40 秒，每个模块有自己的 16 KB 屋顶，新功能直接开新 bank，不再重排。

---

## 1. 为什么必须改（v0.16.5 的实测账）

| 项 | 数值 |
|---|---|
| `_CODE` | `$0400-$3DA5`，余 **603** 字节 |
| `_BANK1` | `$4000-$8011`，**溢出 17 字节**，链接直接失败 |
| `--max-allocs-per-node` | 150000（v0.16.4 是 20000） |
| 全量编译 | **4 分 05 秒**（20000 时 40 秒） |
| 这 150000 换来 | 全工程少 400 多字节，**已经用尽** |

再往上提没有收益：`--max-allocs-per-node` 的边际收益随数值指数衰减，
20000→150000 换来 400 字节，150000→500000 大概只多几十字节，编译时间却翻倍。

真正的问题是**地址空间按 16 KB 计，而不是按 32 KB 计**：`$0000-$3FFF` 和 `$4000-$7FFF`
是两个独立的 16 KB 段，任何一段满了就得从另一段借，借不动就卡死。v0.12.0 以来
每一次「腾地方」都是在这个 32 KB 里挪家具。

---

## 2. 硬件与加载器的事实（这决定方案可行）

| 事实 | 依据 |
|---|---|
| stage1 按**文件大小**把整个 `ezgb.dat` 载入 PSRAM，bank N 落在文件偏移 N×`$4000` | `docs/fpga-stage1.md`（`pf_open` + `fsize` 建簇链） |
| kernel 模式下 `$2000` 是**8 位 bank 锁存**，可映射 256 个 bank | 上游 `docs/kernel-size.md` |
| 上游官方内核 10 bank（160 KB），mod 版 **16 bank（256 KB）**，真机实测通过（含新增第 11 bank 的 far call 测试，FW4/FW5 两台） | 同上，2026-10-30 硬件测试 |
| `$0000-$3FFF` 固定 bank0，永远可见；只有 `$4000-$7FFF` 可切 | GB/MBC5 硬件 |
| 只有 `video.c` 读字模时切过 bank，切换点都在 bank0 | 本工程 `docs/01-architecture.md` |

结论：**扩到 128 KB（8 bank）是纯软件改动**，不需要碰 FPGA、不需要改 stage1，
唯一需要在真机上确认一次的是「128 KB 的 ezgb.dat 能被加载」（上游 256 KB 都行，
风险很低，但要留一次验证窗口）。

## 3. Bank 分配表

原则：**一个功能组一个 bank，模块不跨 bank 拆分**。热的、互相调用密的放常驻段，
冷的、入口少的放可切 bank，用 far call 进出。

| bank | 地址 | 内容 | 当前体积 | 余量 | 切 bank？ |
|---|---|---|---|---|---|
| 0 | `$0000-$3FFF` | `crt0` + `_HOME` + **far 桩表** + `main.c` + `video.c` + `fnt.c` + `fpga.c` | **9.3 K** | **6067** | 永不可切 |
| 1 | `$4000-$7FFF` | `fat.c`（挂载/目录/8.3 名）+ `fatn.c` + `fatx.c` + `game.c` + `savkey.c` + `rtc.c` + `launch.s` | **12.1 K** | **4241** | 默认映射，零成本 |
| 2 | `$4000-$7FFF` | `fatw.c`（簇链分配、目录项写入、簇/扇区读写） | **8.3 K** | ~7.7 K | far call |
| 3 | `$4000-$7FFF` | `save.c`（存档链：prepare / boot / 指纹 / 长名认档） | **3.3 K** | ~12.7 K | far call |
| 4 | `$4000-$7FFF` | **DEBUG 常设**：`diag.c` 自检屏（只在 `--diag` 版编入） | **0.6 K** | ~15.4 K | far call，仅编译期开关进入 |
| 5 | `$4000-$7FFF` | `font_data.c`（字模 1536 字节）+ 预留大字库 | **1.7 K** | ~14.3 K | 数据访问时切 |
| 6 | `$4000-$7FFF` | 业务预留（新功能） | — | 16 K | — |
| 7 | `$4000-$7FFF` | **临时诊断 bank**：一次性 probe / 日志 / 跟踪实验 | — | 16 K | 用完清空，永不进发布 |

改后总量 128 KB，代码占用约 35 K / 128 K（上表是 v0.16.6 实测；改之前 `_CODE` 余 603、
`_BANK1` 余 **-17**）。

### 为什么 `main/video/fnt` 必须常驻

`video.c` 的 `video_char()` 是每个字符一次调用，一屏 360 格；`fnt.c` 读 `EZJR.FNT`
也是逐字调用。这两个模块每秒上千次调用，far call 每次约 40 周期，far 化以后
翻页会肉眼可见地慢。它们和 `main.c`（主循环）、`fpga.c`（端口读写，每个 SD 操作
几十次）一起放 bank0，**互相调用零开销**。

### 为什么 `fat.c` 留在 bank1 而不是 far 出去

`fat_read_sec()` / `fat_cluster_lba()` / `entry_kind()` 这些在目录扫描的 tight loop
里，一次扫描调用几十到上百次。bank1 是 `$4000` 的默认映射，和 bank0 一样常驻、
零切换成本，所以「读路径」整体留在 bank1。

### 为什么 `fatw`/`save` 可以 far

这两个是**冷路径**：建 `SAVER/`、写长名目录项、备份 8 KB 存档 —— 一次开机最多
几次，每次本身就要读写几十个扇区（几百微秒级），far call 的 40 周期完全淹没在
SD 访问里。它们的导出函数也少（`fatw` 6 个、`save` 10 个），桩表小。

## 4. Far call 机制（零参数偏移）

### 4.1 关键设计：只占 1 个返回槽，参数位置与普通 call 完全一致

上游 `FarCallTrampoline`（`$078D`）压 3 个字，导致被调函数第一参数在 `sp+6` 而不是
`sp+2`，所以每个 far 目标的 C 源码都要加两个 dummy 参数占位 —— 这是个持续的坑。

本工程自己实现，**保持 `sp+2`**：

```
调用点：   call  __farcall
           .db   <lo>, <hi>, <bank>, 0      ; 4 字节数据表

调用前栈：  [ret_to_C] [栈上参数...]        ← SP
           同时 DE = 第一个 16 位参数
__farcall:
   pop  hl          → hl = &table（读完 3 字节），栈: [ret_to_C] ...
   pop  hl          → hl = ret_to_C，栈: [栈上参数...]；转存 _far_tmp
   记层：_far_stk[depth] = {ret_to_C, old_bank}
   push __fcret     → 栈: [__fcret] [栈上参数...]
   ld   a,(bank) / ld (0x2000),a
   jp   (target)

目标函数看到：SP → [__fcret]，栈上参数在 sp+2 ✓ 与普通 call 完全一致
             DE 原样 = 第一个参数 ✓

目标函数 ret → __fcret:
   取回 ret_to_C（bc）、恢复 old_bank → ROM_BANK
   push bc / ret    → 回到 ret_to_C，调用者的 add sp,n 照常清栈 ✓
```

因此 **C 源码一行都不用改**，也不需要 dummy 参数。

> **★ DE 是第一个参数的寄存器，不能当临时变量用。**
> SDCC 在 sm83 上把「第一个指针 / 16 位参数」放在 DE 里，栈上只放第 2 个起的参数
> （`fat_info` 的机器码第一条就是 `ld (de),a`）。v0.16.6 用 `pop de` 暂存返回地址，
> 等于把参数指针换成了垃圾 —— 所有带指针参数的 far 调用都往随机地址写，真机上表现
> 为读卡卡在「读取中」。现在全程只用 `hl` / `bc`。
>
> **★ 桩末尾没有 `ret`，返回地址必须从栈上拿，不能按「数据表 +4」推算。**
> 桩是 7 字节（`call` 3 + 数据 4），`&数据表 + 4` 正好是**下一个桩的开头**，
> 跳回去会撞进下一个 `call __farcall`，整张桩表连环错乱地跑。

### 4.1.1 参数与返回值寄存器（v0.16.10 补的账）

上面那张图只画了栈，把寄存器省略了，于是踩了两次坑。完整的约定（实测 `.asm`
得出，不是推理）：

| | 寄存器 |
|---|---|
| 参数 | `A` = 第 1 个 8 位；`DE` = 第 1 个 16 位；`BC` = 32 位参数的**高半**（低半在 `DE`）；第 2 个起的参数压栈 |
| 返回 | `A` = 8 位；`BC` = 16 位；`BC:DE` = 32 位 |

所以 `__farcall` 进门要先把 `A/BC/DE` 存进 RAM（`_far_pa`..`_far_pe`）、切完
bank、装好目标地址之后再原样放回；`__fcret` 同理，先把返回值存起来，恢复 bank
与 `ret_to_C` 之后再把 `A/BC/DE` 放回，最后 `ret`。

v0.16.9 就是因为少了这一步：

- `__farcall` 里 `ld bc,#_far_stk` 把 32 位参数的簇号高半改成 `$C1xx` →
  `fat_cluster_lba()` 算出天文数字的 LBA → 字库读垃圾扇区 → **中文名整片空白**；
- `__fcret` 里用 `a` 取 `old_bank` → 被调函数的 8 位返回值（FAT 错误码）变成
  bank 号 → 备份屏报「未知错误」。

`tools/farcall_test.py` 现在对 8 / 16 / 32 位三种返回各有一条断言（共 10 项）。
换回 v0.16.9 的 `farcall.s` 跑同一套测试会挂 3 项，失败值正好是 `A=1`、
`BC=$C100` —— 与真机症状逐一对得上。

> 这条经验值得单独记：**寄存器约定不能靠推理，反汇编一眼就能看到，看到就该写成
> 断言**。v0.16.8 的测试只查了「DE 参数没被破坏」，返回值一个都没查。

### 4.2 嵌套

`save.c`（bank3）会调 `fatw.c`（bank2），`fatw.c` 会调 `video.c`（bank0）——
所以 far call 会嵌套。每层的 `{ret_to_C, old_bank}` 存进 WRAM 的 far 栈
（`_far_stk`，4 字节/层 × 4 层 = 16 字节），`_far_cur` 记当前 bank。

深度 4 足够（实测调用链最长 3 层：main → save → fatw）。栈溢出时直接进错误屏
（`_far_sp >= 4` → halt），不静默错乱。

### 4.2b 不能跨 bank 传本 bank 的 ROM 指针（v0.16.13）

far call 传参数本身没问题（寄存器 + 栈照旧），**出问题的是指针指向哪里**：

```c
/* fatn.c（bank1）*/
static const uint8_t sav11[11] = {'S','A','V','E','R', ...};   /* 落在 bank1 的 $6xxx */
...
sv = fat_find_dir(sav11);          /* fat_find_dir 在 bank2，走桩 */
```

桩把 $4000 窗口换成 bank2，再 `jp` 过去。进函数时 `raw11` 的**数值**没变
（还是 `$6xxx`），但 `$6xxx` 现在装的是 **bank2 的字节** —— `memcmp(e, raw11, 11)`
永远不相等，`fat_find_dir()` 返回 0。

真机表现（v0.16.12）：`SAVER/` 明明在卡上，内核说没有 —— 读档读不出来；
备份写完立刻回读校验（`save_verify` → `sav_open` → `fat_find_sav_lfn`）也找不到
刚写的档，屏幕报「备份失败 / 校验失败」。

为什么到 v0.16.12 才炸：v0.16.11 及以前读档第一档是哈希短名（`fat_open_read`，
不传常量），长名那一档**从没被走到过**；v0.16.12 把它提成唯一判据，这条路第一次
在真机上执行 —— 和 v0.16.6 的 far call、v0.16.9 的库代码是同一类：
**从未被执行过的路径**。

| 指针指向 | 跨 bank 传 |
|---|---|
| RAM（`$C000+`，`_DATA`/`_BSS`/`_INITIALIZED`） | 安全，地址不随窗口变 |
| bank0 的 ROM（`$0000-$3FFF`） | 安全，永不切换 |
| **本 bank 的 ROM（`$4000-$7FFF`）** | **危险**，切过去就是别的 bank 的字节 |

`tools/verify_bankptr.py` 扫每份 `.asm`：`call _<far 导出>` 之前紧邻的
`ld de,#_sym`（第 1 个参数）或 `ld hl,#_sym; push hl`（第 2 个起），若 `_sym`
定义在本 bank 的 ROM 段、桩的目标 bank 又不是本 bank，就报错。已接进
`build.sh`（失败即中断构建）与 `tools/verify_all.sh`。

修法的优先级：**把那段逻辑挪进同一个 bank**（各自带一份常量），其次是「先把
常量拷进 RAM 再传」，最差是「给桩加一个 bank 内副本」。v0.16.13 采用的是第一种：
`fatn.c` 自带 `n_find_dir()`，`fat_mkdir()` 从 `fatx.c`（bank1）搬进 `fatw.c`
（bank2）—— 搬完这两个函数都只在本 bank 内被调用，`far_exports.txt` 里也删掉了。

### 4.3 桩表

每个跨 bank 导出的函数一个桩，6 字节：

```asm
_fat_cluster_lba::
        call    __farcall
        .db     0x83, 0x42, 2, 0        ; bank2 内地址，由 -g 注入
```

按当前导出清单：`fatn` 7 + `fatw` 7 + `fatw` 内部 6 + `save` 8 = **28 个桩**
（正式版 27 个 —— `diag_*` 只在 `--diag` 版编进来），每个 7 字节 ≈ 190 字节，
bank0 放得下（余 5.9 K）。

桩**由脚本生成**，不手写：`tools/gen_farstub.py` 读各 bank 的 map 与 `.rel` 的引用记录，
求「bank0/1 引用了、但定义在 bank2+ 的符号」集合，输出 `build/obj/farstub.s`。
新增函数不用改任何配置，重新构建即可。

## 5. 构建流程改造

```
① 逐模块编译（CFLAGS 回到 --max-allocs-per-node 20000）
      常驻模块 → 编进 _CODE / _BANK1
      非驻留模块 → 编进 _CODE（临时名），供单独链接
② 每个可切 bank 单独链接
      sdldgb -b _HOME=0x4000 -b _CODE=0x4200 -b _DATA=0xD5xx …  → 该 bank 的 32 KB raw
      从 map 取该 bank 的符号地址
③ gen_farstub.py 生成 farstub.s（桩表）
④ 主链接：bank0 + bank1 的 rel + farstub.rel + -g 注入的 far 目标地址 → 32 KB
⑤ join_banks.py 按 bank 号拼成 128 KB（文件偏移 N×$4000，空 bank 填 $FF）
⑥ fix_header.py：$0147=0x19 (MBC5)、$0148=0x02 (128KB)
```

**每段独立链接**这一点本工程已经在用（字模 bank 就是这么编的，
见 `build.sh` 第 142-171 行），只是从 1 个扩展 bank 推广到 6 个。

### 5.1 每个可切 bank 必须自足（最容易踩的一条）

一个可切 bank 的代码运行时，`$4000-$7FFF` 里只有它自己。所以它**不能引用任何
别的 bank 的 ROM 符号**（函数或常量）——因为那个符号的地址算出来落在 `$4000+`，
call 过去执行到的是当前 bank 的字节，不报错，但跑飞。

规则：

| 类别 | 做法 | 现状 |
|---|---|---|
| C 库（`memset`/`memcpy`/32 位除法） | 每个 bank 链接时都 `-l sm83`，各带一份 | `.rel` 里是外部引用，独立链接时自动拉入 ✓ |
| UI 字符串 `strings.h` | `static const`，每个模块各编一份 | 已经是 `static` ✓ 天然隔离 |
| RAM 变量（`fbuf`、`g_lfn_buf`、`fat_cwd`） | 都在 `_DATA`（`$C000`），与 bank 无关 | ✓ 跨 bank 共享无碍 |
| 字模（`font_data.c`） | 单独 bank，用 `-g` 注入固定地址 | ✓ 已有机制 |
| 别的 bank 的函数 | **只能通过桩**，由 `gen_farstub.py` 生成 | 新增约束 |

`gen_farstub.py` 因此还要做一次**体检**：把每个可切 bank 的未定义符号与「本 bank
定义 + 桩表」对一遍，出现别的 bank 的符号就报错退出（不让它悄悄链成错地址）。

### 5.2 每个段都必须显式 `-b`（v0.16.9 的真机事故）

独立链接时 `sdld` 只认识命令行里 `-b` 过的段，**其余段一律排到已定位段之后**。
而可切 bank 里第一个已定位段是 RAM 的 `_DATA($D5xx)`，于是没被指定的段会被排到
`$D5xx` 的 RAM 上。`ihx2raw` 只收 `$0000-$7FFF` —— 这些段的内容**不会进 ROM**，
但符号地址照样是 `$D5xx`。

v0.16.9 之前就是这么翻的：SDCC 把 `__divulong` / `__mullong` 放在 `_HOME` 段，
它落在 `$D500`，`fatw` 算簇 LBA 时 `call $D500` → 执行被 crt0 清零的 RAM →
NOP 接 NOP → 跑飞。真机表现是「正在备份」画完立刻黑屏。

固定布局（每个可切 bank 16 KB）：

| 段 | 起址 | 用途 | 上限 |
|---|---|---|---|
| `_HOME` | `$4000` | C 库（乘除法在这里，不是 `_CODE`） | `$4200` |
| `_CODE` | `$4200` | 本 bank 的代码 | `$7000` |
| `_CONST` | `$7000` | 常量 | `$7800` |
| `_INITIALIZER` | `$7800` | 初值镜像（**必须为空**，见下） | `$7900` |
| `_GSINIT` / `_GSFINAL` | `$7900` | 初始化钩子（可切 bank 里没人调用） | `$7A00` |
| `_DATA` / `_INITIALIZED` | `$D100+bank×$200` | 静态变量（crt0 的 gsinit 清零） | 512 字节 |

两条硬规矩：

1. **`_INITIALIZED` 必须为空**。`static uint8_t x = 5;` 会生成 `_INITIALIZED`（RAM）
   + `_INITIALIZER`（ROM 镜像），而 crt0 只搬主链接那一份 —— 可切 bank 的初值没人
   搬，变量会静默变成 0。真需要初值时得给每个 bank 加一次 gsinit 调用。
2. **`_DATA` 不得超过 512 字节**（`BANKRAM_STRIDE`）。下一个 bank 的区就在后面。

`-b` 指定了却没人定义的段会让 `sdld` 告警并返回退出码 2（`set -e` 直接打断构建），
所以 `build.sh` 会先汇编一个只声明 `.area`、不放内容的 `segstub.s` 占位。

`tools/verify_banklayout.py` 把上面这些全变成断言，并额外做两件事：扫 bank 窗口
里的 `call/jp` 有没有指向 RAM 符号；把 map 里的窗口字节与最终 `ezgb.dat` 逐字节
对照（防止「有地址、没内容」这类只在 ROM 里才看得出的错）。

## 6. 编译时间

| | 现在（v0.16.5） | 改后 |
|---|---|---|
| `--max-allocs-per-node` | 150000 | **20000**（v0.16.4 的值） |
| 全量编译 | 4 分 05 秒 | **约 40 秒** |
| 改一个模块后 | 全量重编 4 分 | 只重编该模块 + 它那个 bank 的链接，**十秒级** |
| 单 bank 链接 | — | 6 次 `sdldgb`，每次 < 0.2 秒 |

`--opt-code-size` 保留（体积仍要省，但不靠 `max-allocs` 榨）。

## 7. 风险与验证

| 风险 | 等级 | 处理 |
|---|---|---|
| 128 KB 的 `ezgb.dat` 真机加载不了 | 低 | 上游 256 KB 实测通过；仍需一次真机冷启动验证（先做 P0，用最小改动版验证） |
| far call 栈/返回地址写错 → 随机跑飞 | 中 | 模拟器可测：`emu_test.py` 加一项「far call 往返」用例；桩表的每个符号都跑一次 |

| 字模 bank 号变更漏改 | 低 | `video.c` 两处；`verify_rom.py` 加「bank5 非空」检查 |
| `--diag` 版 | 无 | 自检屏进 bank4，反而**终于有地方放**，`--diag` 恢复可用 |

## 9. 调试代码的 bank 纪律

**结论：常设一个，临时一个，永不与业务共用。**

### 9.1 为什么必须独立

v0.16.3 → v0.16.5 这一轮的痛苦几乎全来自「自检屏和业务代码抢抽屉」：

| 代价 | 实际发生的事 |
|---|---|
| 布局来回搬 | `diag.c` 先进 `_BANK1`，再回 `_CODE`，最后又进 `_BANK1` |
| 引入布局 hack | `--diag` 版把 `_BANK1` 起点挪到 `$4080`，借 128 字节给 `_CODE` |
| 两套配置漂移 | 正式版与 `--diag` 版段归属不同，每改一次要两边各算一遍余量 |
| 功能被砍 | v0.16.5 只好让 `--diag` 直接 `exit 2`：「两段只剩 500 多字节，自检屏要 642」 |

调试代码的三个特性决定了它不该和业务挤在一起：**体积不定**（今天 642，明天加两行就 900）、
**迭代频繁**（改一行就要重编）、**正式版根本不需要**。

### 9.2 两个 bank 的分工

- **bank4 = 常设 DEBUG**：自检屏、状态页、错误码汇总。正式版填 `$FF`，调试版装
  `diag.c`。**两种版本共用同一套 bank 布局**，唯一差别是 bank4 有没有内容 ——
  `build.sh` 里那套 `--diag` 分支、`BANK1_BASE=$4080` 可以全部删掉。
- **bank7 = 临时诊断**：一次性 probe、日志、跟踪实验（这轮 `probe.s`、`--loaddiag`、
  `EZJR_LAUNCH_DIAG` 本来都该住这儿）。用完清空成 `$FF`，**永不进发布包**。

### 9.3 三条纪律

1. **调试代码不被主路径 call**。入口只能是「编译期开关 + 开机按键/条件」，
   正常流程一次都不切 bank。
2. **数据从 WRAM 推，不反向依赖**。主程序在 `_DATA` 留一块 diag 状态块（几十字节），
   diag 只读它 + 调 `video` 输出。debug bank 对业务的依赖就收敛成「读一块 RAM」，
   随时可以整块删掉。
3. **能放 host 侧就不放 ROM**。模拟器能复现的（列表绘制、目录遍历）用
   `tools/emu_test.py` 覆盖；只有「模拟器复现不了、必须真机看」的才写进 bank4。
   `probe.s` 那类一次性验证一律进 bank7，事后删除。

### 9.4 顺带的收益

- 发布包与调试包**结构完全一致**（都是 128 KB、同样的 bank 布局），二进制可以直接
  diff，出问题一眼分清是布局还是代码。
- 以后加自检项不用再问「放得下吗」，只问「bank4 还剩多少」（现在 15.4 K）。

---

## 10. 一句总结

> 现在的问题不是「代码太大」，是「所有代码挤在两个 16 KB 抽屉里」。
> 卡带里有 8 个抽屉（128 KB），只是我们现在只用了两个。
> 把冷模块搬出去，编译从 4 分钟回到 40 秒，每个模块有自己的屋顶。
