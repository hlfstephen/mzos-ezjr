# 界面设计与渲染约定

这一份讲界面**长什么样**和**为什么这么画**。改 UI 之前先读完，尤其是第 5 节的
写 VRAM 时机 —— 那里踩过的坑会把字悄悄吞掉，而且不报错。

---

## 1. 屏幕与坐标

屏幕固定 **20 列 × 18 行**，每格 8×8 像素。因为字形全是 8x8 的，所以「列」就是
「字符数」：一个 ASCII 占 1 格，一个汉字也占 1 格，排版直接按 20 列表算。

**20 列是硬约束**，所有版式都要先算够不够。比如 `2026-11-11 15:30:05` 就是 19 列，
再想加个「设置」按钮就挤出去了 —— 所以年份只显示两位（见第 3 节）。

---

## 2. 两个标签，SELECT 切换

| 标签 | 内容 | 操作 |
|---|---|---|
| **游戏** | 列表 13 行（行 3-15），行 17 显示总数 | 上下选游戏，A 启动 |
| **设置** | 时间（走秒）+ 自动备份两个条目 | 上下换条目，A 按当前条目的按钮 |

选中的标签用 `[ ]` 包住：

```
[游戏]      设置            ← 停在游戏页
 游戏      [设置]          ← 停在设置页
```

界面**不显示按键提示**。两个标签、一个箭头、两行设置，本身就把「能做什么」说清楚了。

### 游戏页

```
行 0  [游戏]      设置
行 1  ━━━━━━━━━━━━━━━━━━━━
行 2                        ← 留空（透气）
行 3  ▶ GBC/               ← 文件夹排在文件前面
行 4     GAMES/
行 5     CRYSTAL.GBC        ← 文件按名字升序
 …
行 14    ZELDA.GB
行 16                        ← 留空
行 17        20 个游戏       ← 只数 ROM，文件夹不算
```

**顺序是「文件夹 → 文件」，两组各自按文件名升序**（v0.12.1 起）。

磁盘上目录项是拷贝顺序，文件夹常常散落在最后，翻两页才看到；文件更是当年
往里拷的先后，找一个游戏得从头扫到尾。现在扫描时先把目录挪到前面，最后对
两段各自做一次插入排序（`sort_range()`，稳定的，同名保持卡上顺序）。
`..` 永远在第 0 格，不参与排序。

排序键是**8.3 短名**，不是中文长名：长名只有当前页那十几项在内存里（`_DATA`
只剩几十字节），而排序键必须对每一项都可得。中文 ROM 的短名是
`K?????~1.GBC` 这种，前缀一样、只差末尾序号，排序后仍保持卡上的先后次序，
不会来回跳。

> 排序之后「磁盘顺序」和「列表顺序」就对不上了，所以长名不能再在扫描时
> 顺手填 —— 那样会整体错位（屏幕显示 A 的名字、按 A 启动的却是 B）。
> `fat_fill_lfn()` 改成按**短名**回目录里配对，顺序怎么变都不会错。

**配对键必须按 11 字节原始短名比，两种短名形状都要照顾到**（v0.12.2 修的坑）：
`same_name()` 反解 `"NAME.EXT"` 填 11 字节时，主名段缺字补**空格**，扩展名段
也得补**空格** —— 目录项里没有扩展名时那 3 字节就是 `$20`。v0.12.1 在扩展名段
用 `0` 兜底，于是：

- **所有文件夹**（无扩展名）都配不上长名 → 名字全是 `GBC193~1` 这种；
- **`.GB` 游戏**（两字符扩展名）同样配不上，只有 `.GBC` 正常。

`tools/fat_host_test.py` 现在同时造 `.GBC` / `.GB` / 文件夹三种带真 VFAT 长名的
目录项，任何一种配不上都会红。

光标走出本页会自动翻页；也可以按 **←→ 整页翻**（← 上一页 / → 下一页）。
翻页后光标留在**同一行**，连按几下 → 就能一页一页往后扫；到第一页 / 最后一页
**停住不绕回**。最后一页通常不满，越界的行号会贴到本页最后一条，不会停在空行上。

> 切标签一直是 `SELECT`。左右键只在游戏页用来翻页、在设置页的编辑态用来选字段，
> 两处在不同标签页，不冲突。

### 子目录浏览

卡上的目录也列进同一个列表，名字后面加一撇 `/` —— 这是唯一区分
"按 A 是进去还是启动"的线索，所以不要省：

```
行 3   ▶ GBC/
行 4     游戏时间/          ← 中文长名 + /
行 5     POKEMON.GBC
```

点了「进去」之后，列表第 0 项固定是 `..`：

```
行 3   ▶ ..
行 4     K 游戏时间.GBC
行 5     ZELDA.GB
行 17        3 个游戏        ← 只数真正的 ROM，目录和 .. 不算
```

| 操作 | 效果 |
|---|---|
| A（光标在文件夹上） | 进入该目录，从第一项重新开始 |
| A（光标在 `..` 上） | 回到上级目录 |
| A（光标在 ROM 上） | 启动游戏 |
| B | 在子目录里随时回上级；根目录按 B 无动作 |

**空目录/纯文件夹层不写字。** v0.12.1 及以前会在屏幕中央画「无游戏」，判据是
`count_roms() == 0` —— 而它只数"能启动的 ROM"，所以**整层都是文件夹时也会打这三个
字**：玩家目光扫过一列目录名，屏幕正中央却说"无游戏"，像目录读坏了（真机反馈就是
`GBC官方游戏全集(1934个)\超级机器人大战` 这一层）。真的一无所有时也不必说：只剩
一行 `..` 本身就说明这层是空的。所以那句话整句删掉了，`STR_NO_GAMES` 一起删。

几个刻意的取舍：

- **`..` 做成一个普通条目**，而不是单独一个按键。这样上下键、翻页、
  计数、长名缓存全都不用为它特判 —— 少一套分支就少一处能出错的地方。
- **最多进 4 层**（`FAT_DIR_DEPTH`）。路径栈每层 4 字节（目录首簇），
  第 5 层按 A 会没反应。4 层够 `GBC/中文名/子目录/` 这种组织法。
- **不显示完整路径**。行 0 被两个标签占着，20 列里塞不下路径；
  进没进目录靠 `..` 和 `/` 就能看出来，符合"界面不放提示"的整体要求。
- **不递归**。只扫当前一层。**真实上限是 64 条**（`GAME_MAX`，`main.c`）——
  列表本体存在 WRAM 的 `games[64]` 里，一条 13 字节；`dir_chain()` 那边还有
  32 个扇区（512 项）的扫描上限，但 64 条总是先到。
  > 所以一个 1934 项的目录只会列出**磁盘顺序的前 64 项**（再在这 64 项里排序）：
  > 真机上看到"只出现一部分目录名"、"排序好像没生效"，都是这一条。
  > 真分页（流式扫描 + 跳过前 N×64 项）尚未实现，见 `CHANGELOG.md` v0.12.2 的
  > 「已知限制」。

### START 菜单

列表页按 START 弹出（整屏，不盖在列表上 —— 20x18 里塞六行菜单、底下露出
半截列表反而更乱）。

配色跟列表一致（白底黑字，`rBGP=$E4`），只靠**上下两条短细线 + 缩进**分层级。
v0.11.0 曾经整屏反色（`rBGP=$1B`）+ 左右竖边框，真机反馈是「像进了另一个
程序」，v0.12.0 全部收回：不反色、没有竖边框、两条线只画中间 16 列。
diag 版多一项「自检」。

```
行 0   [游戏]      设置        ← 白底黑字，跟列表同一套
行 1  ━━━━━━━━━━━━━━━━━━━━  ← draw_tabs 的粗线
行 2
行 3
行 4    ────────────────    ← 上细线（SYM_HLINE，只占 col 2-17）
行 5
行 6  ▶ 运行上次游戏
行 7
行 8     ─ K口袋妖怪.GBC      ← 名字行：空格─ 引导 + 缩进第 6 列，上下不加框
行 9
行 10   删除当前文件
行 11
行 12   自检                 ← 只有 --diag 版有这一行
行 13
行 14   ────────────────     ← 下细线（正式版在行 12）
行 15
行 16        B 返回           （正式版在行 14）
行 17
```

- **不反色怎么跟列表分开**：靠两条细线和缩进，不靠颜色。DMG 的 tilemap 没有
  逐格属性，同一行里做不出「灰字黑字」，所以层级只能用位置表达。
- **两条线为什么画短**：顶到屏幕边缘的两条通栏线看着像「又一层边框」，而且
  20 列被挤成 18 列可写区。现在只画 col 2-17（`MENU_RULE_C` / `MENU_RULE_N`），
  上下各留 2 列白边。
- **文件名不是同级菜单项**：行首「空格─」引导符号（col2 空、col3 一条横线），
  缩进到第 6 列（菜单项从第 2 列起），**上下都不画框线** —— v0.11.0 那两根线
  夹出来的更像一个输入框，真机反馈点名要去掉。
- **首次按 START 不出乱码**：`save_boot()` 拿 `$1F0` 的 base8 名校验整组
  「上次游戏」元数据，擦除态（新卡 / 刚刷机）一律作废，菜单显示
  「无上次游戏」，连名字行和细线框都不画。
- 项 1 的文案分两种：有记录 →「运行上次游戏」，没有 →「无上次游戏」
  （按了也不会有动作，所以干脆说清楚）。
- 项 2 也分两种：光标在 ROM 上 →「删除当前文件」，在文件夹 / `..` 上 →
  **「目录不能删」**。直接说结果，比按下去没反应清楚。
- 上下切换只挪 `▶`（`menu_cursor()` 三个 `put_tile`，先把三行的 col 0 清空
  再画箭头 —— 没有竖边框之后，那三格是真正的空白），不重绘整屏。
- B 关菜单返回列表；START 再按一次也当取消。
- 删除后行 17 闪一下「已删除」，1 秒后恢复成计数。

#### 「运行上次游戏」是直接启动

v0.10.0 会「切到上次游戏所在目录 → 重扫列表 → 按名字找」，但元数据里只存了
8 字符基本名（`POKEMON`），跟列表里的完整 8.3 名（`POKEMON.GBC`）永远
`strcmp` 不上，结果玩家只是被送到那个目录、什么都没启动。

现在元数据页多存了 `$180` 的完整 8.3 名，`fat_locate()` 拿「目录簇 + 完整名」
直接在目标目录里定位 ROM 并填一条临时 `GameEntry`，**全程不碰 `fat_cwd` /
`games[]` / `cursor`**：启动成功就不返回，启动失败画完错误屏后主循环重画的
还是按 START 之前那个列表。文件被删 / 换了卡就安静回列表。

`save_prepare()` 盖章时要临时把 `fat_cwd` 设成目标目录，否则 `META_DIR` 会把
子目录里的游戏记成「根目录的」，第二次按 START 又找不着。

### 设置页

```
行 0   游戏      [设置]
行 1  ━━━━━━━━━━━━━━━━━━━━
行 2                        ← 编辑时才用：光标 ▼
行 3  26-11-11 14:30:05 设置
行 4                    ━━  ← 焦点线
行 5
行 6  自动备份  自动      设置
行 7                    ━━  ← 焦点线
行 8
行 9  MZOS V0.14.0 FW5     ← 内核版本 + 固件版本（只读）
```

两个条目的按钮都右对齐到列 18-19，焦点用**按钮正下方的粗线**表示 —— 加方括号
`[设置]` 会多占两列，时间那行就放不下了。

行 9 是 `MZOS <内核版本> FW<固件版本>`，v0.12.0 加、v0.12.2 定成现在的写法：

- `V0.12.3` 是**本内核**的版本（`main.c` 的 `MZOS_VER`），**跟发布号同步**，
  补丁号也写进去。v0.12.1 只写到 `V0.12`，真机上刷了两版补丁却看不出差别，
  只能靠回忆。整行 `MZOS V0.14.0 FW5` 占 16 列，20 列放得下；
- 版本号后面的列位置不是写死的，由 `VER_COL`（按 `sizeof(MZOS_VER)` 算）给出，
  以后改版本号不用动绘制代码；
- `FW5` 是 **FPGA 固件**版本（`fw_version()` 读页 4 首字节）。**十进制不补零**：
  v0.12.0 用的 `print_dec2` 会把 5 写成 `05`，看着像另一台机器；
- 读不到（`$FF`，比如模拟器里根本没有 FPGA）写 `FW--`，不写 `FW255`。

前面标 `MZOS` 是为了跟官方固件的「固件版本」区分开，别让人把它当成内核版本。
整行只读、不带按钮，不参与上下选条目。

### 时间：走秒 + 编辑

不编辑时，时间每秒跟着 PCF8563 走；**只重画行 3 的 17 格**，不闪。

按 A 进编辑后：

```
行 2     ▼                  ← 光标指在「月」上
行 3  26-11-11 14:30:05 保存
```

- 时间**冻结**（不再跟 RTC）；
- 左右选字段：年 → 月 → 日 → 时 → 分 → 秒 → **保存按钮**（再右回年）；
- 上下改值（按字段上限回绕，`rtc_field_max()`）；
- 光标停在「保存」上按 A：写回 PCF8563 + 推算星期，按钮变回「设置」，时间重新流动；
- 任何位置按 B：放弃修改，还原成进入编辑前的值。

字段在行 3 的列位置：年 0、月 3、日 6、时 9、分 12、秒 15；保存按钮 18。
光标 ▼ 就画在对应列的上方（行 2）。

### 自动备份

按 A 在「自动 / 手动」之间切换，状态存在 PSRAM 元数据页的 `$120`/`$121`：
**两个字节都是 `$5A` 才算自动，其余一律算手动。**

默认值是**手动**。这个方向是刻意的：PSRAM 掉电（电池没电）后这两个字节会衰减成
随机值或 `$FF`，于是自动落回「手动」—— 最多多问一句，绝不会不问自取地写卡。
反过来的话，掉一次电就会把「手动」悄悄变成「自动」，下次开机直接覆盖卡上存档。

为什么用两个字节：单字节时随机值恰好等于 `$5A` 的概率是 1/256，误判成「自动」
就会擅自写卡；两个字节降到 1/65536。

手动模式下开机时，如果确实有存档要写（章在、指纹对不上），先问一句：

```
        备份存档          ← 行 5，cjk_center_wide
    K 口袋妖怪 水晶.GBC   ← 行 8，中文全名（无长名则退回过滤过的短名）
         A=备份           ← 行 11
         B=跳过           ← 行 13
```

标题、中文全名、两个按钮都是汉字；`A=` / `B=` 是 ASCII。不再有 `BACKUP` / `SKIP`
英文提示。备份屏的长名来自启动游戏时写进 PSRAM 元数据页 `$130` 的 VFAT 长名
（见 `docs/10-cjk-filename.md`），不是 8.3 短名，所以不会出现 `K?????~1` 那种乱码。

按 B 跳过时**不更新指纹**，所以下次开机还会再问 —— 不会悄悄丢掉一次存档。

### 进度屏 → 完成屏（同一屏，不换画面）

确认（自动模式则跳过确认）之后画进度屏，行 8 居中「正在备份」。备份结束
**不清屏、不重绘整屏**，只在下面局部补结果：

```
        正在备份          ← 行 8，screen_backing_up()
         完成             ← 行 10，screen_save_result(0)
```

结果放行 10 而不是紧贴的 9：8px 汉字上下几乎顶满格子，行 8/9 挨着会糊成一坨。

失败时行 10 是「备份失败」，行 12 再补原因，同样是同一屏：

```
        正在备份
        备份失败
        校验失败
```

原因按 `err` 取值：`FAT_ERR_VERIFY` →「校验失败」、`FAT_ERR_NO_SPACE` →「空间不足」、
`FAT_ERR_ADD_DIR` →「目录已满」、其余 →「未知错误」。**不再显示 `ERR=n`** ——
正式版没有自检屏，`ERR=05` 对玩家等于没说；要精确码就用 `--diag` 版。

这样备份完成时玩家看到的是「同一屏上多出一行」，而不是闪一下换成另一个画面。
三屏绘制都在 `video.c`（真机与模拟器共用），`save.h` 的 `save_boot()` 注释也按此。

**电池没电时不问。** `save_boot()` 里电池哨兵（`$A201 != $88`）的判断在确认屏
之前，直接 `return`：此时芯片里那堆字节是随机垃圾，问"要不要备份"等于问"要不要
把卡上的好存档换成一堆乱码"。屏幕上只会闪过一句 `BATTERY DRY / NOT BACKED UP`，
不用按任何键，1.5 秒后自己消失（而且只在确实有待备份的痕迹时才出现）。

### 错误屏

两个错误屏都只留两行：**中文标题 + 一句人话原因**。原来标题下面还挂一行
`MOUNT FAILED` / `LAUNCH FAILED`，再下面一行 `ERR=n` —— 同一句话说了两遍，
而错误码对玩家等于没说，v0.10.0 起连 diag 版也不显示了（要错误码看自检屏）。

```
        启动失败            ← 行 6，cjk_center_wide
       不是游戏卡           ← 行 9，cjk_center
```

```
       存储卡错误
      无法识别此卡
```

| 屏幕 | `err` | 原因行 |
|---|---|---|
| 启动失败 | `GAME_ERR_BAD_ROM` | 不是游戏卡 |
| | `FAT_ERR_FRAGMENTED` | 文件太碎 |
| | `FAT_ERR_BAD_CHAIN` | 文件已损坏 |
| | 其余 | 未知错误 |
| 存储卡错误 | `FAT_ERR_NO_SIG` | 无法识别此卡 |
| | `FAT_ERR_FAT12` | 格式不支持 |
| | `FAT_ERR_GPT` | 分区表不支持 |
| | `FAT_ERR_NO_FS` | 卡上没有分区 |
| | 其余 | 未知错误 |

区分「无法识别此卡」和「格式不支持」是有用的：前者擦卡重来，后者换台电脑
重新格式化。diag 版的存储卡错误屏只在底部多一行 `ST:DIAG`，一眼看出刷的是
自检版；错误码本身要进自检屏看。

标题 `cjk_center_wide`（每字后空一列）、原因 `cjk_center`（紧凑），
一宽一紧就在视觉上分出层次，不用再加分隔线。

> `STR_*` 数组元素是 glyph id，`0` 是串结束符 —— 所以**文案里不能混 ASCII**。
> 需要写「FAT」「MBR」的地方一律换成汉字说法（格式 / 分区表）。

## 3. tile 分配表

VRAM 一共 256 个 tile（16 字节/个，`$8000` 起）。现在的分配：

| 区间 | 用途 | 数量 |
|---|---|---|
| `$00` | 空白（清屏、擦除） | 1 |
| `$01-$0B` | 界面符号 `▶ ─ ━ █ ▄ ▀ ▌ ▐ ▲ ▼ ●` | 11 |
| `$0C-$1F` | 汉字动态池 **A 段** | 20 |
| `$20-$7E` | ASCII（编号 = 字符码） | 95 |
| `$7F-$FF` | 汉字动态池 **B 段** | 129 |

ASCII 深色能直接拿字符码当 tile 号，是因为 `$20-$7E` 恰好 95 个、且紧接符号区，
`print_at()` 一行查表都不用。

**汉字池被 ASCII 劈成两段**，用 `pool_slot()` 把池内序号映射到 tile 号（0-19 → A 段，
20-148 → B 段）。一共 149 格：中文文件名一屏可能有上百个不同汉字（13 行 × 8 字），
池小一点就会在翻页时反复作废重传。

界面汉字用 86 个（含错误原因、备份屏文案、START 菜单），`CJK_COUNT` 必须 ≤ 149，
`gen_font.py` 会检查。

## 4. 灰阶

GB 只有 4 级灰：白 / 浅灰 / 深灰 / 黑。`rBGP = 0xE4` 是恒等映射，所以 **tile 里的像素值
就是屏幕上的灰阶**（0 白、1 浅灰、2 深灰、3 黑）。

界面文字统一用像素值 3（黑）。曾经做过一套"浅色 ASCII"（像素值 2）给列表里没选中的
行用，v0.6.0 为了让汉字池扩到 149 格（中文文件名）把它砍了 —— 那 95 格 tile 给了汉字。
选中与否现在靠行首的 `▶` 区分。

要恢复浅色，得把 `$7F-$FE` 的 128 格从汉字池还回去，中文名就装不下一屏了。二选一。

## 5. 写 VRAM 的时机（重要）

LCD 开着时，VRAM 只在 **mode 0/1/2** 可写，**mode 3（约 172 周期/行）写入会被硬件整格丢弃，
不报错**。这是本工程唯一一个「错了也看不出来」的地方。

### 整屏换内容 → 关 LCD 写

`video_off()` → 清屏 + 全画 → `video_on()`。360 格 + 字库上传，逐格等 STAT 会跨七八帧，
看得见刷屏；关掉 LCD 就没有竞态，只是黑一两帧（肉眼几乎无感）。

### 局部改写 → 等 VBlank（mode 1）

```c
static void put(uint8_t *p, uint8_t c)
{
    if (rLCDC & 0x80)
        while ((rSTAT & 3) != 1)    /* 只等 VBlank */
            ;
    *p = c;
}
```

**为什么不能等「mode 3 结束」**：mode 3 之后是 HBlank，只有 204 个周期；从读完 STAT 到
字节真正落进 VRAM 要 20 多个周期。如果读 STAT 那一刻已经走到 HBlank 末尾，写入就掉进
下一个 mode 3 —— 实测 18 格丢 2 格，屏幕上是 `PO EMON.GB`，而且**每次丢的位置一样**
（时序是确定的，所以看起来像排版 bug，其实不是）。

VBlank 有 1140 个周期，后面紧跟的 mode 2（OAM 扫描）**也允许**访问 VRAM，所以从 VBlank
起手连写绝不会踩到 mode 3。一次 VBlank 大约写得下 45 格。

`rLCDC & 0x80` 那个判断不能省：LCD 关着时没有 mode 1，会死等。

### 只变一两格 → 直接写

光标移动只改 2 个字节（旧行擦箭头、新行画箭头），走 `put_tile()`，必定落在同一个 VBlank 里。
**不要**为此重画整行 —— 那是 33 格，会跨帧。

时间页每秒刷新也只写行 3 的 17 格（一次 VBlank 内完成）。

## 6. 汉字排版

8px 汉字的字形几乎顶满 8×8，两个字紧贴会糊成一团（「游戏」「设置」这类笔画密的尤其明显）。
所以有紧凑版和宽间距版两套：

| 函数 | 用法 |
|---|---|
| `cjk_puts` / `cjk_center` | 字与字相邻。用于按钮上的「设置 / 保存」、计数「个游戏」 |
| `cjk_puts_wide` / `cjk_center_wide` | 每个字后面空一列。用于标签栏、条目名、状态行、错误标题 |

标签栏的坐标就是这么算出来的（`游@1 空@2 戏@3`，`设@9 空@10 置@11`），改文案要重新对。

## 7. 待办：CGB 彩色 / 中文文件名

**彩色**：在 CGB/GBA 上以 DMG 兼容模式运行时，主机会套一个默认配色，界面本身没有分区上色。
要真彩色需要 header `$143` 置 `$80` + 初始化 BG 调色板 + 写 VRAM bank 1 的属性图，改 header
会改变主机的启动模式，**必须真机验证**，所以一直没动。

**中文文件名**（已做，见 [10-cjk-filename.md](10-cjk-filename.md)）：FAT 的 8.3 短名只能是
ASCII，卡上的中文名存在 VFAT 长文件名项（UTF-16LE）里。现在 `fat_page_names()` 会把它拼回来，
字模从 SD 卡上的 `EZJR.FNT`（U+4E00–U+9FFF 全量，164 KB）按需读。字库文件不在时自动退回
显示 8.3 短名，其它功能不受影响。

为此汉字池从 53 格扩到 **149 格**（`$0C-$1F` + `$7F-$FF`），代价是砍掉了那 95 格浅色
ASCII（原来只有错误屏的原因行在用，现在统一黑色）。

## 8. 调试屏

`diag.c` 整个文件被 `#if EZJR_DIAG` 包住，而且 `DIAG=0` 时根本不在
`build.sh` 的源文件列表里 —— 正式版一个字节都不占，省约 780 字节：

```sh
./build.sh              # EZJR_DIAG=0，不编 diag.c
./build.sh --diag       # EZJR_DIAG=1，START 菜单多一项「自检」
EZJR_TEST=1 ./build.sh  # 强制 1（emu_test.py 要读自检屏里的寄存器镜像）
```

入口是 **列表页 START → 菜单第三项「自检」**（v0.10.0 起）。START 只有一个，
让它先出菜单比在同一个键上绑两个功能清楚；正式版菜单里没有这一项。
另外「存储卡错误」屏上按 START 也能直接进自检屏（方便卡有毛病时定位）。
