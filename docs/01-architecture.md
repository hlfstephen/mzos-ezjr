# 架构：从 KB 到屏幕

本内核是一个 **32 KB、单 bank、ROM-only（cart type `0x00`）** 的 Game Boy 程序。
EZ-Flash 的 stage1 / 工厂引导把它当作普通 ROM 加载进执行槽，从 `$0100` 进入——
所以它不需要任何 MBC 逻辑，也不做运行时的 bank 切换。

---

## 1. 启动链

```
$0100  nop / jp $0150          由 crt0.s 写入（GB 头之后的第一条指令）
$0150  init:
       di                      关中断（全程轮询，不用中断）
       ld sp, $E000           栈放 WRAM 顶
       xor a / ldh ($FF),a    IE = 0
       call gsinit            初始化 C 全局变量（_INITIALIZER -> _DATA）
       call _main
       halt 死循环
```

中断向量 `$0040/$0048/$0050/$0058/$0060` 全部是 `reti`，即使意外触发也不会跑飞。

---

## 2. 段布局

32 KB ROM 在 GB 上是**两块固定映射的 16 KB**：`$0000-$3FFF` 与 `$4000-$7FFF`。
本内核把「读/显示/UI」放在第一块，「写路径/存档/启动」放在第二块 —— 这只是**链接期
分区**（`sdcc --codeseg BANK1`），运行时不切 bank，也不需要 trampoline。

| 段 | 地址 | 内容 |
|---|---|---|
| `_HEADER` | `$0000-$014F` | 中断向量、Nintendo logo、GB 头 |
| `_HOME` | `$0150-$0380` | `init`、`gsinit`（必须 < `$0400`） |
| `_INITIALIZER` / `_GSINIT` / `_GSFINAL` | `$0380-$03A5` | C 全局变量初值 |
| `_CODE` | `$0400-$3D3A` | `main.c` / `video.c` / `fat.c` / `fatn.c` / `rtc.c` / `game.c` / `fpga.c` / 字库数据 |
| `_BANK1` | `$4000-$7F69` | `save.c` / `fatw.c` / `fatx.c` / `launch.s` |
| `_DATA` / `_BSS` | `$C000-` | 全局变量（`games[64]`、扇区缓存、长名缓冲），3750 / 3840 字节 |

> `_CODE` 从 `$0400` 起而不是 `$0200`：给 `_HOME` + `_GSINIT` 留足空间，避免加功能后
> 撞上代码段。

**两段都贴边了**：正式版 `_CODE` 余 710、`_BANK1` 余 151 字节；`--diag` 版 `_CODE` 余 68、
`_BANK1` 余 7 字节。再要加功能只能
做多 bank（stage1 按文件大小加载整个 `ezgb.dat`，`$2000` 是 8 位 bank 锁存）。

`_DATA` 顶端必须避开 `$D000` 起的 handoff 区（`launch.s` 复制到那里执行），`build.sh`
会检查。

## 3. 硬件访问层（`fpga.c`）

EZ-Flash 的 FPGA 寄存器都在 `$7F00-$7FFF`，而且**写前要解锁、写后要提交**：

```
$7F00 = $E1 ; $7F10 = $E2 ; $7F20 = $E3      ; unlock
$7Fxx = 值                                   ; 真正的寄存器写
$7FF0 = $E4                                  ; commit
```

用到的寄存器：

| 寄存器 | 含义 |
|---|---|
| `$7F30` | SD 映射：1 = 扇区数据映射到 `$A000`，3 = 读状态，0 = 关闭 |
| `$7FB0-$7FB3` | LBA（小端） |
| `$7FB4` | 扇区数（bit7 = 1 表示写） |
| `$7FC0` | `$A000` 窗口显示的 PSRAM 页：0/2/4/6… |
| `$7FD0` | bit0 = 1 触发 PicoBlaze 写 PCF8563（设置时间） |
| `$7FD3/$7FD4` | FW5 快加载键 |
| `$7F36/$7F37` | 加载命令提交 / MBC 与 RAM 掩码 |

SD 读一个扇区：`$7F30=1` → 写 LBA → `$7F30=3` → 轮询 `$A000` 直到不等于 `$E1`（忙）
→ `$7F30=1` → 从 `$A000` 拷 512 字节 → `$7F30=0`。

SD 写一个扇区是同一套顺序，区别在 `$7FB4` 的 bit7、以及**编程完要空转一段**（照上游
实测的 350 次循环，不要改成「读回比对」代替）。

> **窗口与 SD 是同一个 `$A000` 地址**。所以 `sd_read()` / `sd_write()` 动手前一律把
> `$7FC0` 清 0（`sd_window()`）—— 否则 PSRAM 页还映射着，数据会写进 PSRAM，屏幕照样
> 报「完成」。v0.12.x 排查过一整轮「备份成功但卡上没有」，最后就是这类「静默换路」
> 叠出来的，详见 [07-save.md](07-save.md)。

## 4. 显示层（`video.c`）

- 屏幕 20×18 个 8×8 tile，tilemap 在 `$9800`，tile 数据在 `$8000`（LCDC = `0x91`）。
- **字形全部 8×8，一个汉字占一格**。界面字模来自 Fusion Pixel Font 8px，ROM 里 1bpp
  8 字节/字，上传时展开成 2bpp。
- **tile 分配**：`$00` 空白；`$01-$0B` 符号；`$0C-$1F` 汉字池 A 段；`$20-$7E` ASCII
  深色（编号 == 字符码）；`$7F-$9F` 汉字池 B 段；`$A0-$FE` ASCII 浅色；`$FF` 空闲。
- **两档字色**：同一份 1bpp 位图上传两遍 —— `low=high=位图` 得像素值 3（黑），
  `low=0/high=位图` 得像素值 2（深灰）。列表里没选中的行用浅色，选中的用深色。
- **游戏名的汉字不在 ROM 里**：`fnt.c` 按码点从卡上的 `EZJR.FNT` 读 8 字节字模
  （字库全量 U+4E00–U+9FFF，164 KB，见 [10-cjk-filename.md](10-cjk-filename.md)）。
  没有这个文件就退回 8.3 短名，不影响开机。
- **写 VRAM 的时机**（最容易踩）：LCD 开着时只有 mode 0/1/2 可写，mode 3 写入被硬件
  整格丢弃且**不报错**。
  - 整屏换内容 → `video_off()` 关屏写；
  - 局部改写 → 等 **VBlank（mode 1）**。不能等「mode 3 结束」：那之后的 HBlank 只有
    204 周期，从读完 STAT 到字节落进 VRAM 要 20 多周期，踩到末尾就丢格
    （`POKEMON.GBC` → `PO EMON.GB`）。

## 5. 文件系统（`fat.c` / `fatw.c` / `fatx.c` / `fatn.c`）

四个文件按职责切开，全部是手写的 FAT16/FAT32 子集：

| 文件 | 职责 |
|---|---|
| `fat.c` | 挂载（MBR → BPB → FAT 类型）、目录扫描、8.3 名解析与比较、排序、LFN 回配、`fat_cwd` 目录栈（4 层） |
| `fatw.c` | 簇链分配/释放、目录项分配与写入（含 VFAT 长名）、目录扩簇、`.sav` 读写 |
| `fatx.c` | 建目录（`SAVER/`）、删文件（连 LFN 项与簇链）、按目录簇定位 ROM |
| `fatn.c` | 按 8.3 名回扫目录取 ROM 的**完整**长名（`.sav` 同名用，编在 `_CODE`） |

### 挂载

1. 读 LBA 0，校验 `$55AA` 与每扇区 512 字节；
2. 若 `$1BE+4` 分区类型非 0，按 MBR 跳到分区起始（`0xEE` = GPT，直接报不支持）；
3. 解析 BPB 得每簇扇区数、保留扇区、FAT 数、根目录项数、FAT 大小、总扇区；
4. 按**数据簇总数**判 FAT12/16/32（`<4085` / `<65525` / 其余），FAT12 不支持；
5. FAT16 根目录是连续扇区，FAT32 是簇链。

### 目录项

过滤规则：跳过已删除（`$E5`）、卷标（`$08`）、LFN（`$0F`）、隐藏/系统（`$02`/`$04`）；
**只读（`$01`）不能跳** —— 很多 ROM 文件带只读位。

**8.3 短名可能是 GBK 字节直塞**。真机上 `K口袋妖怪…gbc` 的短名是
`4B BF DA B4 FC D1 FD B9` + `GBC`，7 个字节 > `0x7E` —— 这是卡上的加载器按**字节**
截断生成的。所以：

- 短名配对时主名段、扩展名段无内容的部分兜底必须是**空格 `$20`**（不是 `0`），
  否则文件夹与 `.GB` 永远配不上长名（v0.12.2 修的就是这一行）；
- 记录里的名字按**字节**存、按字节比较，不假设 ASCII。

### 写目录项（v0.13.0 重写）

照 ChaN 的 FatFs 的 `dir_alloc` / `dir_next` / `dir_register` 拆分：

| 函数 | 职责 | FatFs 对应 |
|---|---|---|
| `dir_seek()` | 只查找同名项，返回 1/2 | `dir_find` |
| `dir_alloc()` | 找 n 个连续空槽，**`$E5` 与 `$00` 同等**，允许跨扇区 | `dir_alloc` |
| `dir_put()` | 按扇区拆开写 n 条 LFN + 短名项 + 1 条 `$00` 终止符 | `dir_register` |
| `dir_append()` | 链尾接一簇并清零 | `create_chain` + `dir_clear` |

核心只有一句：**`$00` 不是什么需要「腾位」的东西，它就是一个能用的空槽**。写满之后
后面本来还有 `$00`，目录终止符自己就往后走了；不够就扩一簇，新簇清零后是一整片空槽。

早期版本（v0.12.6/v0.12.7）在这里绕了两次弯子，把 `$00` 改写成 `$E5` 想「挪追加位」，
结果把目录终止符推出了簇外，删光存档也报「目录已满」。教训写在
[07-save.md](07-save.md)。

## 6. 存档链路（`save.c`）

PSRAM 的元数据页（`$7FC0 = 0x11` 映射到 `$A000`）是内核与「上次运行」之间的唯一
持久存储：

| 偏移 | 用途 | 来源 |
|---|---|---|
| `$000` | 待备份章 `$AA` | 官方 |
| `$001` | 要 dump 的 8KB 块数 | 官方 |
| `$00F` / `$010+` | 文件名长度 / 文件名（ASCII） | 官方 |
| `$110` | 3 字节内容指纹 + 1 字节有效标记 | 本项目 |
| `$120` | 自动备份开关（写两份） | 本项目 |
| `$201` | 电池哨兵 `$88` | 官方 |
| `$300` / `$320` | **上次运行的 ROM 完整 8.3 名 + 目录簇**（18 字节，写两份） | 本项目 |

> `$A110-$A2FF` 是官方**从未写过**的空档。v0.11–v0.12.3 的记录全落在这段里，四版都
> 「写了读不回来」。搬到 `$A300`（官方 `LASTROM` 的位置）一次就通了。

流程：

```
游戏启动前   save_prepare()   读 ROM 头 $0149 → 块数 → 把 .SAV 装进 PSRAM
                              → 在元数据页盖「待备份」章 + 记下这次的名字/目录
下次开机     save_boot()      查电池哨兵 → 有章才备份（自动或问一句）
                              → 指纹相同就跳过 → 写 SAVER/<ROM 名>.sav → 校验
```

`.sav` 的名字**不存副本**：`save_boot()` 用记录里的 8.3 名回目录现查完整长名
（`save_last_lfn()`）。PSRAM 里那份 UCS-2 长名在真机上读不回来，v0.12.1 起就不存了。

## 7. 时钟（`rtc.c`）

读：`$7FC0=6` 后 `$A008-$A00E` = 秒/分/时/日/星期/月/年（BCD）。秒寄存器 bit7 是
`VL`（Voltage Low，掉电后时钟不可信），界面据此提示「请设置时间」。

写（设置时间）：

```
$7FC0 = 6
$A008-$A00E = 7 个 BCD          ; 硬件锁存到 rtc_set_* 寄存器
$7FD0 = 1                       ; rtc_set_go 上升沿 -> PicoBlaze 中断
$7FD0 = 0
$7FC0 = 0
```

PicoBlaze 收到命令 `$10`（`cmd_set_rtc`）后通过 I2C 写 PCF8563 的寄存器 2-8。

**游戏内 RTC 基准**（MBC3+TIMER）：启动前把同一组时间写进页 6 的 `$A018-$A01C`
（日/时/分/秒 + 标志），让游戏从当前真实时间起算，而不是从 0。

星期不入库储存推算结果再读取，而是**由年月日实时算**（0=周日…6=周六），避免
「日期改了星期没跟着变」。

## 8. 主程序（`main.c`）

两个标签共用一套 `get_key()`（按下沿 + `wait_release` + 3 帧去抖），主循环非阻塞：

- **游戏列表**：↑↓ 移光标、←→ 翻页、A 进入目录或启动、B 返回上级、START 弹菜单、
  SELECT 切标签；
- **设置页**：←→ 选字段、↑↓ 改值、A 保存（推算星期后写回）、B 取消；另有自动备份开关；
- **START 菜单**：运行上次游戏 / 删除当前文件 / 自检（`--diag` 版）；
- **提示屏**：备份确认、备份进度与结果、电池没电、错误原因，全中文。

列表上限 `GAME_MAX = 64` 条（`games[]` 在 WRAM），目录栈 4 层。
