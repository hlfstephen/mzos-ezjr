# 05 · 真机测试指南

> **现状**：下面四项（引导 / SD 读 / RTC 读 / RTC 写）都在 v0.6.x 前后通过了，
> 完整清单见 [03-verification.md](03-verification.md) 第 4 节。这一页保留为
> **回归清单**——换卡、换固件、加功能之后按它重跑一遍。
> 自检屏字段在 v0.13.0 减配了（只剩 FW / MOUNT / REC / LFN / FAT+SPC / T / D）。

当年要回答的问题，模拟器一个都答不了：

| # | 待验证 | 为什么模拟器测不了 | 失败后果 |
|---|---|---|---|
| 1 | **引导**：FPGA 工厂引导能否把这个 32 KB 的 `ezgb.dat` 装进执行槽，并从 `$0100` 跑起来 | PyBoy 直接把 ROM 当卡带跑，没有"引导加载内核"这一层 | 开机停在 `LOADING...` 或黑屏 |
| 2 | **SD 读**：`$7FB0` 命令 + `$A000` 数据窗口的读扇区序列 | 模拟器没有 SD 控制器，`$A000` 读回 `$FF` | 列表为空 / 挂载失败 |
| 3 | **RTC 读**：页 6 `$A008-$A00E` 是否真给 PCF8563 的 BCD | 模拟器没有 PCF8563，测试版用 RAM 镜像顶替 | 时间显示乱码/全 0 |
| 4 | **RTC 写**：`$7FD0=1` 是否真让 PicoBlaze 经 I2C 写进 PCF8563 | 同上 | 设完时间断电就丢 |

> **v0.5.0 的操作**：两个标签（游戏 / 设置），**SELECT 键切换**，界面上没有按键提示。
> - 游戏页：上下选游戏、A 启动、**←→ 整页翻**；光标走出本页也会自动翻页。
> - 设置页：上下在两个条目间移焦点，A 按当前条目的按钮。
>   - 时间条目按 A 进编辑：时间冻结，**左右**选字段（年→月→日→时→分→秒→保存），
>     上下改值，在「保存」上按 A 写回；按 B 放弃。
>   - 自动备份条目按 A 在「自动 / 手动」间切。
> 自检屏默认**不编进 ROM**，要进自检屏得先 `./build.sh --diag` 出一版，
> 然后在游戏列表按 START 打开菜单、选第三项「自检」。

## 0. v0.2.1 修了什么

真机按 A 后能到 GBC 开机画面，但 **Nintendo logo 空白、游戏跑不起来**。
用真实 2 MB ROM 做端到端验证（`tools/e2e_rom_test.py`：构造 FAT 镜像 →
跑 `fat.c`/`game.c` → 按命令表重组 → 与源文件逐字节比对）**完全一致**，
说明算法链是对的，问题在"读到的目录项本身错了"。

根因：`fat_scan_games()` 的根目录扇区表只开了 16 项，而 FAT16 根目录是 32 个
扇区（512 项），遍历按 32 走 → `chain[16..31]` 读到栈上其它变量当 LBA。
越界读会命中任意扇区，若数据像目录项就会凭空造出一个"游戏"，首簇是垃圾，
启动它装的就是别处的数据。已改为 32 项并加 `ci < nchain` 边界。

同时新增**启动诊断屏**：按 A 启动时先显示 10 行数字停 3 秒（按 A 立刻继续）。

### 诊断屏字段

```
MODE 128  PG 2        $7F32（bit7 = kernel mode）/ $7FC0，命令窗口的两个使能
LD 1                  $7F36，加载窗口
SZ 2097152            文件大小（字节）
CL  67                首簇
T 16 R 06 A 03        ROM 头 $0147 / $0148 / $0149（十进制）
MB 03 RM 127 RR 03    MBC 码 / ROM bank 掩码 / RAM 掩码
CK 40 EX 01           卡带头校验和 / 加载命令段数
LBA 67                第一段起始扇区
RD 00                 命令写进 $A000 后的回读：0 一致，1 窗口没映射、写丢了
```

| 组合 | 结论 |
|---|---|
| `MODE` 不是 128 或 `RD 01` | 命令窗口没映射，FPGA 拿到空命令 → 查 `$7F32` 保持与窗口使能 |
| `RD 00` 但 `T`/`SZ` 不对 | 读到了错的扇区（簇号或 LBA 算错） |
| 全部正常、`RD 00`、仍然进不去 | 软件侧无问题，转查 FPGA 装载与 `$7FC1/$7FC2` 的 bank 掩码 |

## 0. v0.1.2 修了什么

上一版真机回报 `存储卡错误 / MOUNT FAILED / ERR=01`，自检屏是
`SEC0 00 00 00 00 00` + `SIG=55AA OK`。这组读数的含义很明确：

- `SIG=55AA OK` → SD 读扇区的链路**是通的**，真的读到了 LBA0 的末尾两字节；
- `SEC0` 全 `00` → LBA0 的引导代码区是 0，也就是**带分区表的卡**（MBR 的引导
  代码区常被格式化工具填 0），而不是"整卡一个卷"的裸卷；
- `ERR=01` → `fat_mount()` 走了"无签名"分支。

问题在判据上：旧代码要求 LBA0 的 `0x0B` 处等于 512（那是 FAT 引导扇区里的
"每扇区字节数"），可是 MBR 那块装的是 x86 引导代码，那里几乎永远不是 512。
于是**所有带分区表的正常卡都会被判成"不是 FAT"**。

现在改成：先判断这是不是 FAT 引导扇区（`0x36`/`0x52` 处的 `FAT` 标签，标签缺失
时用 BPB 关键字段自洽兜底），认不出来才当 MBR 取第一个分区项；`0xEE`（GPT 保护
分区）单独报 `ERR=3`。主机侧补了 6 种卷布局的回归（裸卷 / MBR / 无标签 / GPT /
分区非 FAT / FAT12），其中 MBR 那条就是照这次真机的读数造的。

## 1. 准备

### 1.1 卡

- microSD，**FAT16 或 FAT32**（FAT12 会直接报 `MOUNT=2`；GPT 分区报 `MOUNT=3`）。
- 根目录放 **2 个以上** `.gb / .gbc`——一个都没有就测不出列表，只能测错误屏。
- 建议再放 **14 个以上**，这样才能测到翻页（每页 13 行，第 14 条开始进第 2 页）。

### 1.2 备份现在能用的内核

开机前先把卡根目录的 `ezgb.dat` 挪走（改名为 `ezgb.dat.bak`，或直接拷到电脑）。
它是你正在用的 **1.04c 中文内核 + RTC 补丁**：

```
md5  45173449173fae2c02f8dade19ce5897
大小 557056 字节（34 banks）
```

> 本测试包 `restore/` 里也放了一份同样的文件，两者 md5 应一致；不一致就说明
> 你卡上的内核和我这边打包的不是同一个版本，**以你卡上的为准**。

### 1.3 上卡

把本包的 `ezgb.dat`（32768 字节，32 KB）拷到卡**根目录**，覆盖同名文件。

> 文件名必须是 `ezgb.dat`。EZ-FLASH 的工厂引导只认这个固定名字（`docs/ezgb-dat-boot.md`），
> 不像 [lukesau/ezgb](https://github.com/lukesau/ezgb) 重写的 stage1 那样支持多个 `*.dat` 让用户挑。

## 2. 开机与期望画面

上电后会先看到工厂引导的 `LOADING...`，然后内核接管。屏幕应当变成：

```
        中文内核                <- 行 0-1：标题（居中）
EZ JR KERNEL FW 5               <- 行 2：固件版本（读到 4 或 5）
游戏列表 3 个文件               <- 行 3：中文表头 + 计数
> POKEMON.GBC                   <- 行 5 起：11 行一页，8.3 短名
  TETRIS.GB
  ...
UP/DN:SEL L/R:PAGE              <- 行 16
A:RUN B:TIME ST:DIAG            <- 行 17
```

对照自己的屏，按现象分流：

| 看到的 | 含义 | 去做 |
|---|---|---|
| 停在 `LOADING...` / `ezgb.dat not found` | 引导层没读到/没加载这个文件 | 查：文件名是否为 `ezgb.dat`、是否在根目录、文件是否 32768 字节 |
| 花屏、白屏、满屏噪声 | 内核跑起来但 LCD/VRAM 初始化异常 | 记录并回报（T0） |
| 完全黑屏 | 内核没跑起来，或卡在 `video_init` | 记录并回报（T0） |
| 出现中文界面但列表空、顶部显示 `0 个文件` | 引导 + SD 通，但目录解析没命中 | 进自检屏记录 `MOUNT` 与 `FAT/SPC` |
| 出现「存储卡错误」+ 一句中文原因（无法识别此卡 / 格式不支持 / 分区表不支持 / 卡上没有分区） | 扇区 0 读到了但不是合法 FAT 卷 | 进自检屏（START）看 `MOUNT`（1 = 扇区 0 读到了但不是合法 FAT 卷） |
| **界面正常、列表有条目** | 引导 + SD + 字库全通 | 继续 T1–T10 |

## 3. 检查项

逐项打勾，任何一项不符就把编号写进回报里。

| # | 操作 | 期望 | 说明 |
|---|---|---|---|
| **T0** | 开机 | 出现中文界面 | 引导是否成功 |
| **T1** | 看行 2 | `FW 5`（或 `FW 4`） | 显示 `--` = 页 4 读不到，固件版本寄存器异常，但**不影响**其它功能 |
| **T2** | 数列表条数 | 与根目录 `.gb/.gbc` 数量一致（上限 64） | 少了 → 属性过滤/长名截断问题 |
| **T3** | 连按 ↓ 到底，再按 ↓ | 光标循环回到第一项，画面不闪乱码 | 光标重绘路径 |
| **T4** | 光标停在第 13 项时再按 ↓（≥14 个游戏） | 自动翻到第 2 页，第 14 项成为首行 | 翻页（光标走出本页自动翻） |
| **T4b** | 在第 1 页按 **→**，再按 **←** | → 整页跳到第 2 页、光标仍在同一行；← 回到第 1 页。第 1 页按 ←、末页按 → 都**停住不动** | 手动翻页（v0.14.0）。只有两页时按四下就该停住，不能绕回 |
| **T5** | 按 **SELECT** | 标签 `[ ]` 移到「设置」，显示时间（**每秒在走**）和自动备份 | 页 6 RTC 窗口 |
| **T6** | 核对显示的时间 | 与手机/电脑时间误差 ≤ 2 秒 | **RTC 读通**；差几分钟 = 时钟本身在走但初值错；全 `00` 或乱码 = 读不到 |
| **T7** | 看有没有「请设置时间」提示 | 没有 | 有 = `VL=1`，电池掉过电（**先换电池**再继续，否则 T9 无意义） |
| **T7b** | 设置页看「自动备份」那条 | 显示 **手动**（新刷入 / 掉电后都是手动，见下） | 默认手动，只有明确选过「自动」才记忆 |
| **T7c** | 设置页按 A 切到「自动」，**拔电 30 秒**再开机 | 回到 **手动** | 设置记在 PSRAM，掉电就丢 —— 这是物理限制，安全方向 |
| **T8** | 在设置页按 A 进编辑 → 按 → 移到「时」→ 按 ↑ 改 +1 → 一路按 → 到「保存」→ 按 A | 行 17 显示「已保存」，按钮变回「设置」，时间继续走；再进编辑看值 = 改后的 | **RTC 写链路（`$7FD0`）** |
| **T9** | **关机拔电 30 秒**，再开机看时间 | 时间继续走，且从你设的值起算 | 断电保持 = 真的写进 PCF8563 了，不是只改了窗口 |
| **T10** | 按 START 打开菜单（**需 `--diag` 构建**），下移两次选「自检」按 A | 进自检屏，记录全部字段 | 见下表；这张屏是排障的主要证据 |
| **T11** | 选一个**小游戏**（俄罗斯方块这类，32–64 KB），按 A | 屏幕熄灭 1–3 秒，然后**游戏画面出现**，能按键操作 | **本轮的核心目标**。熄灭期间是 FPGA 在流式装载 |
| **T12** | 进游戏后玩 30 秒，翻几个画面 | 画面正常、声音正常、不重启 | 花屏/错乱 = 加载命令的段表算错了（段表第二项是累计值） |
| **T13** | 选《宝可梦 水晶》这类 MBC3 游戏，按 A | 能进游戏（**时钟会是 0 起点，这是 P1 的已知边界**） | MBC3 能进 = `$7F37` 的 MBC 码与 timer 位写对了 |
| **T14** | 回内核后选一个**碎片化**的 ROM | 显示「启动失败 / 文件太碎」，3 秒后自动回列表 | 段表上限保护，不该崩 |

> **T11 是本轮的核心。** 它之后的两步（FPGA 流式装载、`$7FE0` 复位接管）
> 在 PyBoy 里完全不存在，所以这是整个项目唯一没有模拟器兜底的环节。
> 失败时的现象对照：
>
> | 现象 | 最可能的原因 |
> |---|---|
> | 按 A 后画面一直黑，不恢复 | handoff 没跑起来，或 `$7F36=3` 没触发。先确认 T1 的 `FW` 不是 `--` |
> | 花屏 / 半屏乱码 | 加载命令的段表错（第二项写成段长而非累计值），或 `$7FC1/$7FC2` 的 bank 掩码小 |
> | 进游戏后立即重启循环 | `$7FC3` 校验和错，或 `$7F32` 时序问题 |
> | 游戏能进但存档报错 | 正常：`$7FC4` 给了 RAM 掩码，但本版不落盘（P2） |
> | 显示「文件太碎」 | ROM 碎片超过 61 段。把文件拷到电脑再拷回来通常就连续了 |
> | 显示「文件已损坏」 | FAT 簇链损坏（下一簇是 0 或越界），卡需要检查 |

> **T8/T9 是最关键的一步。** 它验证的是 `$7FD0=1 → PicoBlaze 命令 $10 → I2C 写寄存器 2-8` 这条链。
> 如果 T8 通过但 T9 失败（断电后回退），说明写只落在 FPGA 的窗口寄存器里、没进芯片。

## 4. 自检屏字段判读（START → 菜单 → 自检，任意键返回）

> **v0.13.0 起这屏减配了**：SEC0 / PT / SIG / CL / PART / RTC 原始 BCD / VL /
> WDAY / B= / V= / DIR= 全部去掉（32KB 的 BANK1 只剩 6 字节，而那些项在 v0.11
> 之前就验证完）。现在只留 **FW / MOUNT / REC / LFN / FAT+SPC / 解码后的 T、D**。
> 需要旧版式时按 CHANGELOG 里 v0.12.7 的提交取回 diag.c。

### 怎么进自检屏（三步，缺一不可）

1. **刷 diag 版**：`./build.sh --diag`，把产出的 `build/ezgb.dat` 覆盖到卡上
   （测试包里就是 `diag/ezgb.dat`）。
2. **开机，等游戏列表出来**。
3. **按 START** 打开菜单 → 按 ↓↓ 选到第三项「自检」→ 按 A 进入，
   **按任意键**返回列表。

> 正式版按 START 只会打开菜单（两项：运行上次游戏 / 删除当前文件），
> **没有「自检」这一项** —— `diag.c` 在 `EZJR_DIAG=0` 时根本不参与编译，
> `main.c` 里的入口也一起被条件编译掉。省下的约 780 字节是给汉字字库腾的。
>
> 也就是说：**手上那张卡如果不是 `--diag` 版，菜单里就没有自检**。
> 排障时先确认刷的是 `diag/ezgb.dat`，别在正式版上找第三项。
>
> 另一条入口：卡有问题时先出的是「存储卡错误」屏，在那屏上按 START 也能
> 直接进自检屏（不用先回列表）。
>
> 进不去时的自检顺序：① 卡上 `ezgb.dat` 的 MD5 是否等于 `MD5SUM.txt` 里
> `diag/ezgb.dat` 那一行；② 是不是刷完没重新插卡；③ 电池有没有电（START
> 读取不依赖 RTC，但黑屏可能是别的原因，见第 3 节）。

**没有二级菜单。** 自检就是这一屏只读信息，不提供选项 —— 它要解决的是
"卡在哪一步读错了"，不是"让我改点什么"。所有字段一次性打出来，拍照即可。

```
自检
FW=5                行 3   页 4 首字节，1-9 有效，-- 表示读不到
MOUNT=0             行 4   返回码：0 成功 / 1 无 55AA / 2 FAT12 / 3 GPT / 4 分区里不是 FAT
REC=OK              行 8   「上次启动」记录读回来了没
LFN=OK              行 9   回目录现查长名命中没
FAT=16  SPC=8       行 10  卷类型 / 每簇扇区数
T=15:30:05          行 13  按 BCD 解码后的时间
D=2026-11-11        行 15  解码后的日期
```

> **v0.13.0 减配了这屏**：`SEC0 / PT / SIG / CL / PART / RTC 原始 BCD / VL / WDAY /
> B= / V= / DIR=` 全部去掉（32 KB 的 `_BANK1` 只剩 7 字节，而那些项在 v0.11 之前就
> 验证完）。现在只留七个会变、且能区分病因的读数。需要旧版式时按 CHANGELOG 里
> v0.12.7 的提交取回 `diag.c`。

判读口径：

| 字段 | 正常 | 异常说明 |
|---|---|---|
| `FW` | `4` / `5` | `--` = 页 4 读不到（FPGA 没进内核模式，或不是 EZ-Flash） |
| `MOUNT` | `0` | `1` = 扇区 0 没有 `55AA`；`2` = FAT12；`3` = GPT；`4` = 分区里不是 FAT |
| `REC` | `OK` | `--` = 记录校验不符，或本次开机后还没进过游戏（新卡/刚刷机就是这样） |
| `LFN` | `OK` | `--` = 记录在，但回查目录没命中。最常见是目录项超过 256（16 扇区窗口），见 [04-boundaries.md](04-boundaries.md) 第 3 节 |
| `FAT/SPC` | `16` 或 `32`，`SPC=1/2/4/8/…/128` | `FAT=--` = 没挂上 |
| `T/D` | 与电脑上的时间一致 | 全 `FF`/全 `00` = 页 6 没映射或芯片没应答；差几分钟 = PCF8563 本身在走，用设置页校一次 |

## 5. 故障对照

| 现象 | 最可能原因 | 下一步 |
|---|---|---|
| 开机 `LOADING...` 卡住 | 引导层读到文件但加载失败；或文件不是 32 KB | 核对文件大小与 `md5sum ezgb.dat`（与发布页 `MD5SUM.txt` 对照） |
| 黑屏但能听到卡通电 | `crt0` 没跑到 `video_init`（栈/`gsinit`/入口地址） | 回报 T0 |
| 界面正常，列表 `0 个文件` | 目录遍历或属性过滤 | 自检屏记 `MOUNT` 与 `FAT/SPC`；告诉我卡上有几个 ROM、什么格式 |
| `MOUNT=1` | 扇区 0 没有 `55AA` 签名 | 自检屏记 `MOUNT` |
| `MOUNT=4` | 有分区表，但分区起始扇区不是 FAT 引导扇区 | 记 `PT`、`PART`；这卡可能被格成 NTFS/exFAT |
| `MOUNT=2` | 卡被格式化成 FAT12 | 用 SD Card Formatter 或 Windows 重新格成 FAT32 |
| `MOUNT=3` | GPT 分区表 | 转 MBR，或用整卡格式化（superfloppy） |
| `MOUNT=0` 但列表空 | 根目录区定位错（`reserved`/`num_fats`/`fat_sz` 组合） | 告诉我 `CL`、`SPC`、`PART` |
| 中文变方块/花字 | 汉字 tile 上传被 VRAM 写保护打断 | 拍屏回报（可能是 LCD 开关时序问题） |
| 时间读出来慢/快几分钟 | PCF8563 本身在走，但初值不同步 | 不是 bug；用 T8 设一次即可 |
| T8 保存后回读正确、T9 断电丢失 | `$7FD0` 只改了 FPGA 窗口，没触发 I2C | 回报 T8/T9 具体现象，我去查触发时序（可能需要更长的等待或不同的位） |

---

## 6. 收工与恢复

1. 关机，拔卡。
2. 删掉根目录的 `ezgb.dat`（32 KB 那个）。
3. 把备份改名回 `ezgb.dat`（或拷回 `restore/ezgb.dat`）。
4. 开机确认官方中文菜单回来、能正常启动游戏。

> 卡本身不会被写坏：这个内核**只读 SD**（`fpga.c` 里没有 `sd_write`），
> 也不会碰 pSRAM 里的存档。唯一被改的是 SD 卡根目录那个文件。
